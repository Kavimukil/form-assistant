# Tool schema specialization

Builder sorts canonical field IDs, groups exact semantic types and filters writable
fields. Empty setter groups are omitted; clear_field targets every selected writable
field regardless of current value. Allowed canonical action families further restrict
set/clear exposure. Choice/multi-choice oneOf branches correlate each field to its
supplied candidate IDs; labels/aliases never occur in enum values. Truncation is
represented by the candidate IDs, not a separate schema flag. Validator checks the
correlation independently of model/native schema support.

Canonical serialization sorts object keys, preserves deterministic tool/enum order.
Exact canonical JSON is the schema fingerprint, excluding answers, labels, revision
and active-field identity. Goldens are generated by the production builder.

## Native schema simplification experiment (6R.11)

The first frozen live run produced spurious `oneOf` output arguments. Following
plan §7 rule 10, v0.2.1 projects correlated JSON branches to flat candidate enums
for native model declarations. The canonical schema/golden remains correlated;
strict per-field validation remains identical. Candidate unions can express a
broader native space for multiple choice fields, so cross-field membership is
always checked after decoding. A regression test proves foreign candidates are
rejected. Only model formatting changes; corpus/thresholds are unchanged. The
first report is retained, and the simpler variant is evaluated separately.
